## 问题

手工设计一个多智能体系统很费劲：几个角色、谁负责什么、怎么传递信息、按什么顺序。**自动设计智能体系统**就是让 LLM 来搜索这个设计，人只给任务和评价标准。

## 三条自主性

SwarmAgentic 把「完全自动」拆成三条：

1. **从零生成**：不依赖预定义的功能模块，只允许复用和任务无关的最小脚手架（比如输入输出的包装）；
2. **自我优化功能**：单个智能体的角色、职责、策略能根据反馈改；
3. **自我优化协作**：能增删步骤、调整顺序、改依赖关系。

| SwarmAgentic | ✓ | ✓ | ✓ | |

## ADAS 的问题

ADAS（Meta Agent Search）用一个元智能体反复写新的智能体代码，并把**所有**历史设计都存进档案、放进 prompt：

- 档案越来越长，最后会**撑满上下文窗口**；
- 搜索更偏向「新奇」而不是「更好」；
- 跑了 30 轮还是输，说明瓶颈在**搜索效率**，不在预算。

## SwarmAgentic 需要什么

只要两样：**任务描述**和**目标函数**。代码里，每个新领域要提供任务描述、函数说明、一个返回 (分数, 问题) 的 `evaluate()`，和一份数据集。

## 「完全自动」不等于什么都不用人做

- **元框架是人写的、固定的**：角色的格式、顺序工作流的格式、7 类缺陷、8 种编辑操作、所有 prompt；
- 必须有一个**可计算的目标函数**。目标说不清楚的任务，超出了它的适用范围；
- 不用领域模板是一种取舍：论文也承认，没有归纳先验，收敛会慢一些。

## 这是哪种「自我进化」

这是**设计时**的优化：搜索结束后输出一个固定的配置，系统在运行时不会再改自己。和「运行时自我改进」（比如边做边更新自己的提示或记忆）是两回事。
