## 最终分数会掩盖行为

同样是 30 分，可能是从不用工具，也可能是工具用了但证据用错了。所以要拆开每一条轨迹看。分析时用的流水线地图：

1. **决策**：调不调工具？
2. **工具层**：perceive 看到了什么，retrieve 查到了什么？
3. **落地**：把看到的和读到的对上了吗？
4. **收敛**：卡住时会不会换个角度？

## 工具到底用了多少

- `perceive()`：器械检测 78.2%、三元组 95.0%、器械定位 76.2% 的 episode 用了；
- `retrieve()`：阶段识别 72.6% 的 episode 用了；
- 来源选择：动作识别的检索里 80.3% 查的是教学视频；CVS 有 80.8%、技能评估有 66.9% 查的是教材加指南。

## 成功和失败用工具一样多

| | 成功 | 失败 |
| --- | --- | --- |
| 平均工具调用次数 | 2.32 | 2.36 |
| 用了 perceive | 56.4% | 69.8% |
| 用了 retrieve | 71.8% | 65.0% |

失败的反而更爱用 perceive。**差距不在拿不拿证据，而在怎么用证据。**

论文归纳的三个瓶颈：

1. **查询质量**：偏爱「权威文本」，少查视觉案例；
2. **对不完美证据的鲁棒性**：CVS 上，指南的文字会**覆盖**本来正确的视觉理解；
3. **证据落地**：这是最根本的约束。

## perceive 买到的是思考时间，不是视力

- SAM 2 的自动分割**不知道是什么**，只知道哪里有东西；模型也很少真的引用区域编号；
- 两个闭源模型在动作识别上，perceive 有 90%–100% 的时候返回**没有可用的区域**；
- GPT-4o-mini 对「hold」这个动作的召回率，用了工具后从 0.76 掉到 0.07。

改进方向：可提示的 SAM 2（点、框）、视频记忆、加一层 CLIP 式的语义标签。

## 每个模型的工具使用风格不同（内部分析，5 个模型）

| 风格 | 表现 |
| --- | --- |
| 拒用工具 | 近一半的 episode 第 0 步就交卷 |
| 容易打转 | 大量重复调用 perceive |
| 谨慎使用 | 按需调用 |
| 容易被投毒 | 照抄检索到的错误证据 |
| 闭源验证者 | 用检索去**核对**，而不是去**找答案** |

把这些模型平均起来，正负效应互相抵消。**工具效应要按模型报告。**

## 先排除环境的天花板

> 如果动作空间表达不了需要的观测，再好的策略也做不到。

CVS、技能评估、阶段识别需要跨帧追踪和空间提示，现在的工具给不了。这时说「策略不行」，就是**把环境的限制错算成了智能体的限制**。

## 先排除 bug

几个看起来像「能力差」、其实是 bug 的例子：

- JSON 解析的回退只重试 1 次，把 InternVL 的推理结果清空了；
- SAM 2 和 vLLM 抢同一张 GPU，导致 OOM。

所以 InternVL 只开 perceive 的那一列结果要打上括号，单独说明。

## 统计上要小心

按「成功 / 失败」分组的统计是**相关**，不是因果。按任务中心化之后，用检索和成功变成了正相关：不同任务本身难度不同，会制造假的相关。
