## 从 LLM 到 agent

> agent = LLM + 状态 + 工具接口 + 解析约束 + 交互循环

工具调用只是看得见的那部分。一个智能体至少要有四层：

1. **系统提示**：把模型设定成一个会用工具的策略；
2. **工具 schema**（`available_tools`）：定义动作空间；
3. **输出协议**：让输出能被执行，见 [结构化输出](#/n/llm/structured-output)；
4. **环境 / runner**：执行动作、把结果喂回去。

## Harness 的四个维度

| 维度 | 问的问题 |
| --- | --- |
| 工具 | 给它哪些能力？ |
| 控制流 | 谁决定下一步：模型，还是写死的流程？ |
| 状态 | 它能看到哪些历史？ |
| 校验 | 怎么检查它的输出？ |

每个维度都是在**能力**和**可控性、成本**之间取舍。工具分三档：API < 单次 LLM 调用 < 子智能体。原则：**能用 API 就不用 LLM，能用单次 LLM 就不用子智能体。**

读别人的数据构造智能体（比如 SciResearcher）时发现：harness 的大部分成本花在**校验**上（蕴含检查、捷径检测、多个求解器投票），而不是生成上。

## Gym 风格的接口

```python
obs = env.reset(episode)
while True:
    action = agent.act(obs)                                   # 模型决定下一步
    obs, reward, terminated, truncated, info = env.step(action)
    if terminated or truncated or step >= max_steps:
        break
```

每个 episode 的状态是显式的：任务描述、视觉输入、观测历史、可用工具、**剩余预算**、答案格式。工具产生的东西（比如标了号的分割图）累积在观测的媒体列表里。

## 运行时的护栏

- **预算**：`perceive()` 单图最多 2 次、多帧最多 3 次，重复的 (帧, 粒度) 直接拒绝；`retrieve()` 每个来源最多 2 次，总共最多 8 次；
- **去重**：和之前的查询余弦相似度 ≥ 0.95 的，拒绝；
- **强制交卷**：剩下不到 2 步时，只提供 `submit()`；
- **非法调用不结束 episode**：返回 `success=False` 和提示，让模型改。

预算加强制交卷，才把一个开放的工具循环变成**能打分的 episode**。

## 设计上的选择

- **每轮只做一个动作**（顺序的 ReAct 式）：为了可控、好分析。可真实的外科医生是「边看、边查、边想」耦合在一起的，API 其实也支持并行调用；
- **benchmark ≠ 编排框架**：LangChain 是用来搭应用流程的；SurgAgentGym 规定的是 episode 的边界、奖励、日志和协议。benchmark 定规则，agent 来参加测试；
- **prompt 会诱导工具使用**：写了「优先用工具，不要猜」，模型调工具是因为被要求，不是因为缺信息。这时工具调用频率测的是**听不听话**，不是**需不需要**。后续版本放松了这句，直接交卷的比例就上去了。

## 以后怎么训练它

从易到难：prompt / 协议优化 → 行为克隆或轨迹 SFT → 基于奖励的 RL。RL 需要稠密的每步奖励，也要防奖励被钻空子。这条路线和机器人学习是同一个问题：**策略 + 环境 + 奖励**。
