## 问题

隐私红队测试的套路：用越狱 prompt 逼一个大模型说出某个人的隐私（电话、账号、证件号……），再让**评估器**判断回答有没有泄露。评估器通常是 guard 模型或 LLM-as-Judge。

审计靠不靠谱，取决于评估器靠不靠谱。可是泄露常常是**间接的、部分的、编码过的**，同一个回答，不同评估器会给出不同结论。

## 第一步：先量一量评估器有多不一致

- 25K 条越狱 prompt：覆盖 70 种 PII 属性、50 个数据主体、55 种越狱策略；打到 5 个目标模型上，得到 **125K** 个 prompt–response 对。见 [越狱与守卫模型](#/n/llm/jailbreak-guards)。
- 12 个 guard、5 个 LLM judge 两两算 [Cohen's κ](#/n/method/agreement-kappa)：有的对低于 0.2，有的高于 0.8；各个 guard 判「安全」的比例从约 25% 到约 72%，差了将近 3 倍。
- 分歧的两个来源：
  - **能力不够**：Base64、密文、只说一半的输出，评估器读不懂，甚至会「脑补」解码结果；
  - **对隐私的定义不同**：虚构内容、间接帮助、打码、语气恶毒但没泄露……各家判法不一样。见 [什么算隐私泄露](#/n/llm/privacy-leakage)。

## 方法：PrivacyEvalClaw

一个**不需要训练**的审议式智能体（骨干 Qwen3.5-27B），把 guard 模型、解码器、PII 检测器和两个新写的元工具（Privacy_QA_Reasoner、Disagreement_Analyzer）都当成工具：

- 按需调用工具收集证据，而不是一次性打分；
- 工具之间有分歧时，**把分歧当成要调查的问题**，而不是投票；
- 最后输出一份结构化的 JSON 报告：结论、证据、分歧怎么解决的。

细节见 [审议式工具智能体](#/n/agent/deliberative-agent) 和 [工具打架时怎么办](#/n/agent/disagreement)。

## 结果

**和人工标签的一致性**（350 条，218 条泄露 / 132 条没泄露）：

| 方法 | κ | 一致率 |
| --- | --- | --- |
| 12 个 guard 多数投票 | −0.022 | 50.69% |
| 最好的单个 guard | 0.343 | 69.21% |
| 5 个 judge 多数投票 | 0.336 | 70.36% |
| 最好的单个 judge（Qwen3-8B） | 0.599 | 80.34% |
| **PrivacyEvalClaw**（Qwen3.5-27B） | **0.626** | 81.07% |
| **PrivacyEvalClaw**（Qwen3.6-Plus） | **0.708** | 85.43% |

**成对评审**（GPT-5.4-mini 当裁判，比较完整的推理轨迹，胜 / 负 / 平 %）：

| 对手 | 结论 | 过程 | 总体 |
| --- | --- | --- | --- |
| 不用工具 | 46.57 / 27.14 / 26.29 | 98.86 / 1.14 / 0 | 82.86 / 5.71 / 11.43 |
| 不用工具 + CoT | 53.14 / 23.71 / 23.14 | 99.14 / 0.86 / 0 | 84.86 / 3.71 / 11.43 |
| 去掉 guard 工具 | 24.00 / 34.00 / 42.00 | 68.00 / 32.00 / 0 | 64.00 / 32.00 / 4.00 |
| 去掉 Disagreement Analyzer | 25.00 / 42.86 / 32.14 | 62.50 / 37.50 / 0 | 51.79 / 39.29 / 8.93 |

- 12 个 guard 投票，和人的一致性跟扔硬币差不多（κ ≈ 0）：**投票救不了定义不同的评估器**；
- 过程上几乎全胜，结论上没那么明显，对两个消融甚至输得更多。所以**只看成对评审不够**，必须再对一遍人工标签。见 [成对评审：过程 vs 结论](#/n/method/pairwise-judge)；
- 代价：每条样本约 114K token，直接让 judge 判只要约 2.3K，大约 50 倍。

## 最重要的认识

> 评估器本身也是需要被评估的。工具的输出是证据，不是选票。

- 评估器之间一致，不代表它们是对的；只有人工标签才能说明谁对；
- 解码器、正则这类**确定性工具**最客观，模型类工具会「脑补」；
- 一个不训练的智能体，靠好的系统提示和合适的工具，就能超过最好的单个 judge。

## 还没解决的

- 太贵：比直接判多花几十倍 token；
- 什么时候调哪个工具是 prompt 规定的，不是学出来的（论文把「自我进化的 agent harness」列为下一步）；
- 没见过的密文解不了；
- 成对评审没有说明怎么控制位置偏差和长度偏差。
