## 问题

让 LLM 自动设计一个多智能体系统：几个角色、各自负责什么、按什么顺序协作。已有的方法（ADAS、AFlow、EvoAgent、AgentSquare……）都要从**人写好的东西**出发：种子智能体、模板，或者一套固定的算子。

论文把「完全自动」拆成三条：

1. **从零生成**智能体，不依赖预定义的功能模块；
2. **自我优化功能**：每个智能体的职责和工作方式能根据反馈改；
3. **自我优化协作**：工作流能增删步骤、调整顺序和依赖。

已有方法没有一个三条全满足。ADAS 只差第一条：它从七个手写的种子智能体出发。见 [自动设计智能体](#/n/agent/automated-agent-design)。

## 方法：把 PSO 搬到语言空间

- **一个粒子 = 一整套多智能体系统**：角色（名字、职责、策略）+ 顺序工作流 + LLM 编译出来的可执行 `forward()` 代码。见 [整个团队是一个粒子](#/n/agent/system-as-particle)。
- **初始化**：只给任务描述，用 5 个不同温度采样出 5 个粒子，低温偏保守，高温偏新奇。
- **每一轮**：
  1. 每个粒子在小训练集上跑一遍，用目标函数打分；
  2. LLM 读失败案例，归纳出**有类型的缺陷**（缺角色、角色冗余、策略不足、缺步骤……）；
  3. **速度** = 一份自然语言的修改计划，合并三条建议：**失败驱动**（替代惯性项）、向**自己的历史最优**学、向**全局最优**学；
  4. **位置更新** = 按计划改配置，再重新生成代码。
- 5 个粒子 × 10 轮；对比的 ADAS 跑 30 轮。

经典 PSO 见 [粒子群优化](#/n/math/pso)，每一项怎么换成 LLM 调用见 [语言空间里的优化](#/n/llm/language-space-optimization)，失败项见 [从失败中学习](#/n/agent/failure-driven-update)。

## 结果

TravelPlanner 的最终通过率（GPT-3.5 / GPT-4o 执行）：

| 方法 | 最终通过率 |
| --- | --- |
| Direct | 0.0 / 2.2 |
| EvoAgent | 1.1 / 7.2 |
| ADAS | 1.1 / 8.9 |
| **SwarmAgentic** | **3.3 / 32.2** |

- 6 个任务上都是最好的；摘要里的「比 ADAS 相对提升 261.8%」就是 GPT-4o 这一列：$(32.2 - 8.9)/8.9$；
- 结构化、模板就够用的数学题（MGSM）上优势很小：88.4 vs Direct 87.3；
- 搜出来的系统能换执行模型用（Claude、DeepSeek、Gemini）；
- 更便宜：训练总成本 \$8.74 vs ADAS \$11.10，每个任务的验证成本 \$0.567 vs \$1.11；而且 5 个粒子可以并行，ADAS 的 30 轮只能串行。

怎么读这些数字，见 [搜索式设计怎么评测](#/n/method/search-eval)。

## 最重要的认识

> PSO 只需要两个原语：比较两个解的差（diff），按差去改（apply）。LLM 能做这两件事，所以 PSO 能搬到文本里。

- 消融（创意写作 20 题，满分 10）：完整版 8.8；去掉**协作结构重组**掉到 6.7，去掉**智能体级调整**掉到 7.3，去掉**失败驱动项**只掉到 8.4。论文主打的失败项，实证上贡献最小。**叙事上重要的组件，实证上不一定重要。**
- 「完全自动」仍然需要人写的元框架（角色格式、缺陷类型、编辑算子、所有 prompt）和一个**可计算的目标函数**。目标说不清的任务，它做不了。

## 和机器人有什么关系

SwarmAgentic 是纯文本的，没有感知和动作，论文自己也把具身智能体列为以后的工作。能搬过来的是方法：**诊断失败 → 定向修改 → 不重复失败过的修改**，适合在不可微的结构化设计上搜索，比如奖励函数、任务分解、规划器 + 校验器的流水线。

但预算完全不同：这里一次评估是几次 API 调用，机器人学习里一次评估可能是几小时的 RL 训练。只能评估十几次的时候，种群方法吃亏，贝叶斯优化更合适。真正值得带走的是**按缺陷做定向修改**，而不是粒子群本身。

## 读代码时发现的

论文和代码有几处不一致（见各篇笔记）：论文里的随机系数 $r_f, r_p, r_g$ 在代码里不存在，优化器温度是 0.001；论文说角色的名字、职责、策略都能改，代码的 Modify 只允许改策略。
