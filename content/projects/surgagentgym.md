## 问题

通用的多模态大模型（MLLM）到底懂多少外科？外科数据少、涉及隐私、每种手术都要专家标注，没法靠大规模微调解决。所以分两步问：

1. **不训练**，它们现在能做到什么程度？→ SurgKnowBench
2. **给它们工具**（看图分割、查外科知识库），推理时能不能把差距补上？→ SurgAgentGym

就像培养外科医生：先摸底，再看给了「教材和放大镜」之后能不能做得更好。

## 第一阶段：SurgKnowBench

- 把 **11 个公开数据集**统一起来：7 种手术 × 7 类任务（器械检测、器械定位、三元组、手术阶段、动作、CVS、技能评估），整理成一份 376,602 个样本的清单，每类任务有固定的答案格式。见 [外科场景理解](#/n/med/surgical-scene)；
- 零样本评测 **17 个** MLLM（闭源、开源、医学专用）；
- 另外挑出 **952 个**难例，组成 Hard 子集，见 [难例集、对照与统计](#/n/method/hard-set-controls)。

模型保留了一部分物体级的先验，但关系和流程理解很弱：

| 任务 | 最好成绩 | 对照 |
| --- | --- | --- |
| 器械检测 | 26.1% macro-F1 | 多数类基线 13.5% |
| 器械定位 | 22.7% F1@0.5 | |
| 三元组 | 所有模型 < 5% macro-F1 | |
| 手术阶段 | 最好的数据集平均准确率仍低于多数类基线 | |
| CVS | InternVL2.5-8B 准确率 71.2%，**κ = 0** | 只是学会了标签分布 |

指标怎么选才不被钻空子，见 [指标的捷径](#/n/method/metrics-shortcuts)。

## 第二阶段：SurgAgentGym

一个 Gym 风格的环境，智能体每一步调用一个工具：

- `perceive()`：SAM 2 自动分割，再用 Set-of-Mark 在图上标号，见 [MLLM 怎么看图](#/n/llm/mllm-basics)；
- `retrieve()`：在 **SurgWiki** 里检索，74,315 个知识块，来自教材、指南、教学视频和病例，见 [混合检索](#/n/agent/hybrid-retrieval)；
- `submit()`：交答案。

每个 episode 都有调用预算和结构化输出协议，见 [Agent 与 harness](#/n/agent/harness) 和 [结构化输出](#/n/llm/structured-output)。评测 **16 个** MLLM 骨干。

## 结果

- **工具主要帮了偏感知的任务**：器械检测，16 个模型里 15 个提升；动作识别，14 个开源模型全部提升；但 GPT-4o-mini 和 Claude-Haiku-4.5 在器械检测上反而降了 17.7 和 7.6 个点；
- 显著性检验：80 个可检验的格子里，39 个显著提升，1 个显著下降。分任务看：阶段 14/16、动作 14/16、器械检测 10/16、CVS 1/16、技能 0/16；
- **定位、CVS、技能评估**仍然是瓶颈：光给工具，解决不了主观的、需要专家判断的任务；
- 动作识别最好也只有 27.6% macro-F1，还低于多数类基线 30.0%。

## 最重要的认识

> 失败的 episode 和成功的一样频繁地调用工具（平均 2.36 vs 2.32 次）。差距不在能不能拿到证据，而在怎么用证据。

论文总结了三个瓶颈，见 [轨迹失败归因](#/n/agent/failure-attribution)：

1. **查询写得好不好**：智能体更喜欢查「权威文本」，少查视觉案例；
2. **对不完美证据的鲁棒性**：CVS 上，指南里的文字会压过本来正确的视觉判断；
3. **证据落地**：拿到证据之后，能不能把「看到的」和「读到的」对上。

还有两条方法上的：

- 准确率高、κ 接近 0，说明模型学到的是标签分布，不是任务；
- 怪策略之前，先看动作空间能不能表达需要的观测：单帧分割追踪不了跨帧的器械身份，再好的策略也做不了。
