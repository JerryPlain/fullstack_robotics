## 什么时候用成对评审

评估的对象不是一个标签，而是一整段**推理轨迹**：调了哪些工具、怎么解释证据、怎么处理分歧。这种东西很难打绝对分，但让一个裁判模型**比较两段**，相对容易。

## PrivacyEvalClaw 的设定

- 裁判：GPT-5.4-mini；
- 输入：同一个样本的两段完整轨迹，匿名成 `xx` 和 `yy`；
- 明确要求：**不许用人工标签、金标准或外部事实**，只比较两段轨迹本身；
- 输出三个维度的胜者（xx / yy / tie）：**结论**（outcome）、**过程**（process）、**总体**（overall），再加一个置信度；
- 再给四个 1–5 分的维度：证据支持、调查深度、歧义处理、可审计性；
- 两边差不多时必须判 tie。结果按胜 / 负 / 平的百分比报告，平局不算半个胜。

所有基线用**同一个骨干模型**（Qwen3.5-27B），所以差别来自工具和审议，不是模型大小。

## 过程赢 ≠ 结论赢

| 对手 | 结论 胜/负/平 | 过程 胜/负/平 |
| --- | --- | --- |
| 不用工具 | 46.57 / 27.14 / 26.29 | 98.86 / 1.14 / 0 |
| 去掉 guard 工具 | 24.00 / 34.00 / 42.00 | 68.00 / 32.00 / 0 |
| 去掉 Disagreement Analyzer | 25.00 / 42.86 / 32.14 | 62.50 / 37.50 / 0 |

- 过程上几乎全胜，因为裁判模型会奖励**看得见的调查**；
- 结论上，对两个消融，完整版反而输得比赢得多。

所以论文另外做了一张表：最终标签和人工标签的 [κ](#/n/method/agreement-kappa)。**成对评审量过程质量，人工标签量对不对，两个都要。**

## 要警惕的偏差

LLM 裁判有几个已知的偏差，设计成对评审时要控制：

- **位置偏差**：偏向放在前面（或后面）的那个，常用做法是交换位置各评一次；
- **长度偏差**：偏向更长、更详细的回答，而审议式智能体的轨迹天然更长；
- **自我偏好**：偏向和自己同家族模型的风格。

这篇论文没有说明怎么控制这些，读结果时要记住。
