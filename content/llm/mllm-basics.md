## 一个 MLLM 由三块组成

```
图像 → 视觉编码器 (ViT / CLIP / SigLIP) → 投影层 (MLP 等) → 一串视觉 token ┐
                                                                        ├→ LLM → 文本
文本 → 分词 → 文本 token ─────────────────────────────────────────────┘
```

- **视觉编码器**把图像切成 patch，编码成特征；
- **投影层**把视觉特征映射到 LLM 的词向量空间，变成「视觉 token」；
- 视觉 token 和文本 token 拼在一起，**在 LLM 的自注意力里融合**。

推论：**图越多、分辨率越高、长宽比越极端，视觉 token 就越多**，上下文会被图像占满。部署时 prompt 超长，常常就是图像 token 太多，见 [在 SLURM 上跑 vLLM](#/n/infra/vllm-slurm)。

## CLIP 式模型 ≠ MLLM

外科领域的 SurgVLP、PeskaVLP 这类模型是 CLIP 式的**双编码器**：一个图像编码器、一个文本编码器，学的是两者的相似度。它们擅长检索和零样本分类，但**没有解码器、不会生成**，所以没法当智能体去调用工具、写答案。

## 让模型「指着说」：Set-of-Mark

MLLM 直接输出精确坐标往往不准。Set-of-Mark（SoM）的思路：

1. 先用分割模型（这里是 SAM 2 自动模式）把图里的区域都切出来；
2. 在图上给每个区域画轮廓、标上编号；
3. 让模型回答「是第几号区域」，而不是直接报坐标。

SAM 2 的自动分割是**类别无关**的：它知道「哪里有东西」，不知道「这是什么」。所以 SoM 把「在哪」交给分割模型，把「是什么」交给 MLLM。实际用下来，模型很少真的引用区域编号，见 [轨迹失败归因](#/n/agent/failure-attribution)。

## 框的格式

不同模型习惯的坐标格式不一样：有的输出归一化到 [0, 1] 的 (x, y, w, h)，Qwen 系列有原生的 `bbox_2d`（像素坐标的左上、右下）。评测时要按模型原生格式解析，再统一换算，否则格式错误会被当成能力差。

## 和 VLA 的关系

VLA（Vision-Language-Action）模型基本就是同一套结构：视觉编码器 + 投影 + 语言模型，只是输出端从文本换成了**动作**（离散化的动作 token，或者接一个动作头）。所以 MLLM 在视觉理解上的短板（细粒度定位、跨帧追踪），会直接变成机器人策略的短板。
